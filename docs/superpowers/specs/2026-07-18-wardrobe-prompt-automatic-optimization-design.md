# 私人衣橱 Prompt 后端自动优化与顾问回滚设计

## 1. 背景与目标

现有系统已经实现衣物单次 AI 初判、顾问修正、正反例沉淀、效果统计、Prompt 版本、候选生成和离线评估。但 Prompt 优化仍由顾问在小程序中手动点击“生成候选”“开始评估”“发布”，不符合“顾问只负责校准业务数据，Prompt 优化由后端完成”的新要求。

本次调整的目标是：

1. 顾问只审核和修正衣橱评测，不参与 Prompt 的生成、评估和发布流程。
2. 后端根据新增正反例自动生成候选 Prompt，使用隔离测试集自动评估，达到门槛后自动发布。
3. 所有 Prompt 和优化任务保留版本、样本快照、指标与操作记录。
4. 所有已认证顾问都可以把 Prompt 手工回滚到历史版本，回滚必须填写原因。
5. 自动优化或回滚都只影响之后新上传的衣物，不改写历史 AI 初判和顾问结果。

## 2. 不变的业务规则

- 每件衣物只有一次业务 AI 识别机会。Gemini 的超时或限流重试属于同一次技术调用，不形成新业务轮次。
- AI 初判保存后不可覆盖；顾问直接在原评测表中修正并提交最终数据。
- AI 与顾问结果一致记为 `positive`，任一 AI 可识别字段被修改记为 `negative`，AI 没有合法结果记为 `ai_failed`。
- 正例和反例都进入 Prompt 优化数据集。正例用于保留有效规则，反例及字段级差异用于指出需要修正的倾向。
- 离线评估会在历史图片上调用 Gemini，但它是 Prompt 实验，不是该衣物的第二次业务识别；实验结果只写实验表。
- AI、顾问和历史表继续使用已经对齐的同一套评测结构，包括八种独立风格分数以及衣型、色彩、花朴、主辅色、特例和季节等字段。

## 3. 方案选择

### 方案一：每次顾问提交后立即同步优化

实现简单，但顾问提交会被昂贵的 Gemini 调用阻塞，并且少量样本会频繁生成无意义版本，不采用。

### 方案二：事件触发、后端异步合并优化，并由定时任务补偿

顾问提交成功后只发出“新增评审样本”事件。后端异步检查样本门槛，同一时间只运行一个优化任务；定时扫描负责恢复服务重启前未完成的任务。这一方案实时性、稳定性和实现复杂度较平衡，作为本次采用方案。

### 方案三：仅按固定时间批处理

运行稳定，但演示时需要等待固定周期，而且无法及时利用新数据，不采用。

## 4. 总体架构

新增 `WardrobePromptAutoOptimizer` 作为自动流程编排器，复用现有候选生成、离线实验、版本切换和统计服务，不把所有逻辑塞入顾问完成接口。

编排器包含以下职责：

- 接收顾问完成评测后的事务提交事件。
- 判断是否达到样本门槛以及当前是否已有运行中的优化任务。
- 固化训练样本和隔离测试样本 ID，创建自动优化任务。
- 依次执行候选生成、离线评估、门槛判断和事务化自动发布。
- 记录失败原因、指标、发布决定和执行时间。
- 在应用启动和定时扫描时恢复可继续执行的任务。

顾问完成接口只负责保存最终评测、生成正反例并提交事务。自动优化失败不能导致顾问评测回滚或提交失败。

## 5. 自动优化流程

1. 顾问提交评测，后端生成 `positive` 或 `negative` 样本。
2. 数据事务提交后发布内部事件，异步编排器开始门槛检查。
3. 编排器使用数据库锁或唯一运行标记，保证同一时间最多有一个自动优化任务。
4. 只统计上次成功创建优化快照之后新增的、`single_pass_v2`、已完成且 AI 与顾问数据完整的正反例。
5. 开发和测试环境默认达到 4 个新增样本且正反例各不少于 1 个时触发；生产环境默认达到 20 个新增样本且正反例各不少于 3 个时触发。门槛通过配置项覆盖。
6. 最多选取最近 50 个合格样本作为候选生成集，并保存不可变的样本 ID 快照。
7. 候选生成器接收当前 active Prompt、聚合偏差、代表性正例和反例，输出候选 Prompt 与优化摘要。
8. 从未进入本次候选生成集的历史样本中选择隔离测试集。开发和测试环境至少需要 2 个成功测试样本，生产环境至少需要 10 个；不足时任务保持 `waiting_for_holdout`，不发布候选。
9. 基准 Prompt 和候选 Prompt 在同一批隔离图片上分别运行，均与顾问最终结果比较；实验数据不修改衣橱业务记录。
10. 全部门槛通过时，后端以 `system:auto-optimizer` 为操作者在事务中自动激活候选版本并退役旧版本。
11. 未通过时将候选标记为 `rejected`，保留 Prompt、样本、指标和失败原因，不影响当前 active 版本。

定时补偿任务只推进已有任务或重新检查等待样本的条件，不重复创建相同样本快照的任务。

## 6. 自动发布门槛

候选只有同时满足以下条件才能自动发布：

- 隔离测试成功样本数达到当前环境的最小值。
- 实验失败率不高于 20%。
- 候选 `styleMae` 不高于基准版本。
- 候选 `exactMatchRate` 不低于基准版本。
- 两项核心指标中至少一项严格改善，避免相同结果反复生成新 active 版本。
- 候选输出全部通过现有评测结构校验，包括只出现八种风格、只保留 1 至 2 个非零风格以及枚举值合法。
- 候选的父版本仍是当前 active 版本；若评估期间 active 已被回滚或切换，本任务记为 `stale`，不得覆盖新状态。

门槛值及其快照写入优化任务。以后调整配置不会改变历史任务为什么发布或未发布的解释。

## 7. 顾问人工回滚

### 权限

回滚暂时开放给所有顾问，不使用管理端 `users` 账号。这里的顾问是登录时通过现有 `grade=1` 校验并获得云函数短期顾问令牌的用户。请求必须携带该令牌，后端继续校验顾问资格，普通用户不能调用。操作者使用顾问 `openid` 记录。

### 操作

1. 顾问在 Prompt 版本列表中选择一个 `retired` 历史版本。
2. 页面展示目标版本、当前版本、发布时间、关键指标和 Prompt 差异。
3. 顾问点击“回滚”，必须填写非空原因并再次确认。
4. 后端重新校验顾问身份及目标状态，在同一事务中锁定版本表、退役当前 active、激活目标版本并写入审计记录。
5. 接口返回新的 active 版本，页面刷新版本状态。

回滚只影响回滚完成后新创建的 AI 衣橱任务。历史衣物仍关联当时实际使用的 Prompt 版本。

### 防止自动反弹

人工回滚后，自动优化进入样本冷却期。只有回滚之后又积累到当前环境规定的新增样本门槛，才允许创建下一次候选；正在运行且基于旧 active 版本的任务全部标记为 `stale`。这样不会在顾问刚回滚后立即自动切回被撤销的版本。

## 8. 数据模型调整

### `qj_wardrobe_prompt_version`

- 状态扩展为 `candidate`、`evaluating`、`active`、`retired`、`rejected`。
- 保留父版本、来源、生成摘要、创建人、发布人和时间。
- 自动发布的 `published_by` 为 `system:auto-optimizer`；人工回滚的发布人记录顾问 `openid`。
- 继续使用唯一 active 约束，任意时刻只允许一个生效版本。

### `qj_wardrobe_prompt_optimization`

增加或明确：

- `trigger_type`：固定为 `automatic`。
- `status`：`pending`、`generating`、`waiting_for_holdout`、`evaluating`、`published`、`rejected`、`stale`、`failed`。
- 训练样本 ID、测试样本 ID 和配置门槛快照。
- 基准与候选指标、发布判断、失败原因、发布版本和各阶段时间。
- 任务使用的 base Prompt 版本，确保可复现和并发检查。

### 新增 `qj_wardrobe_prompt_version_audit`

每次版本切换写一条不可变记录：

- `action`：`auto_publish` 或 `manual_rollback`。
- `from_version_id`、`to_version_id`。
- `actor_type`：`system` 或 `advisor`。
- `actor_id`：系统标识或顾问 `openid`。
- `reason`：自动发布记录门槛摘要；人工回滚记录顾问填写的原因。
- `optimization_id`、操作时间。

## 9. 接口与前端调整

### 后端内部流程

- 顾问完成评测后触发自动优化事件，不增加顾问等待时间。
- 候选生成、离线评估和发布改为后端内部调用，不再依赖前端串联 HTTP 接口。
- 原手工创建候选、启动优化、启动评估和手工发布接口停止给小程序使用，并在兼容期返回明确的“已改为后端自动处理”错误，防止旧前端误操作。

### 顾问小程序

Prompt 中心保留以下内容：

- 全局识别效果统计。
- 当前 active Prompt 和历史版本列表。
- 自动优化任务状态、基准与候选指标、发布或拒绝原因。
- 历史版本详情和人工回滚入口。

移除以下按钮：

- 生成候选 Prompt。
- 开始离线评估。
- 发布候选 Prompt。

回滚按钮只在 `retired` 版本上显示。确认框包含必填回滚原因，并明确提示“只影响之后上传的衣物”。

## 10. 一致性与错误处理

- 顾问评测事务和自动优化任务解耦；自动任务创建或 Gemini 调用失败不能影响已完成评测。
- 候选生成或实验失败时保留任务和错误信息，active Prompt 不变。
- 发布与回滚必须使用数据库事务和行锁；唯一 active 约束作为最后一道保护。
- 每个任务保存训练集和测试集快照，两者必须无交集。
- 应用重启后，定时补偿会恢复 `pending`、`generating` 和 `evaluating` 任务；超过超时时间且无法恢复的任务标记为 `failed`。
- 同一任务、同一样本的实验结果保持唯一，重复调度不会重复计数。
- 顾问令牌无效或过期返回 401；顾问资格服务未配置返回 503；回滚目标状态已变化返回业务冲突，不执行部分切换。

## 11. 测试与验收

### 单元与集成测试

- 顾问完成评测只保存一次业务 AI 结果，并在事务提交后触发事件。
- 未达到新增样本门槛时不创建候选。
- 达到门槛且正反例齐全时只创建一个自动任务。
- 训练集和测试集无重叠，样本 ID 快照不可变。
- 候选任一核心指标变差时不发布并标记 `rejected`。
- 指标均不变时不发布，至少一项严格改善且其他门槛通过时才自动发布。
- 评估期间 active 版本改变时任务标记 `stale`。
- 发布、并发发布和回滚后始终只有一个 active 版本。
- 所有有效顾问令牌可以回滚；普通用户、伪造令牌和过期令牌不能回滚。
- 回滚原因缺失时拒绝操作，成功回滚后生成完整审计记录。
- 人工回滚后的冷却期能够阻止旧任务立即重新发布。
- 自动优化失败不改变顾问评测和衣橱历史数据。

### 端到端验收

1. 在测试库制造满足门槛的正反例，确认顾问页面没有人工优化按钮。
2. 后端自动生成候选并完成隔离评估。
3. 使用一组通过门槛的数据验证自动发布，确认新上传衣物记录新 Prompt 版本。
4. 使用一组未通过门槛的数据验证 active Prompt 不变且拒绝原因可见。
5. 任一顾问选择 retired 版本、填写原因并回滚，确认之后上传的衣物使用回滚版本。
6. 确认回滚前的历史衣物、AI 初判、顾问结果、正反例和实验结果均未被改写。

## 12. 本次范围边界

- 本次不实现模型微调或训练 Gemini，只通过数据驱动的 Prompt 生成和离线评估优化行为。
- 本次不允许顾问直接编辑 Prompt 文本，也不保留人工发布候选的入口。
- 本次不引入管理端账号权限；回滚按用户确认，暂时开放给全部已认证顾问。
- 本次不重跑或覆盖任何历史业务 AI 初判。
